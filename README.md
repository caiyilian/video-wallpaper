# video-wallpaper

把视频设成 Windows 桌面动态壁纸的轻量工具。**不依赖任何第三方软件**（不用 Wallpaper Engine、不用 Lively），
只用系统 API + PySide6，把视频窗口挂到桌面图标下方那一层。

```
python wallpaper.py
```

无参数直接运行。启动后常驻系统托盘，右键托盘图标可暂停 / 换视频 / 选显示器 / 开关机自启。

---

## 资源占用（本机 1920×1080@60Hz，4K60 源片转 1080p60 后实测）

| 指标 | 数值 |
|---|---|
| 磁盘新增 | **0 MB**（复用已有 Python venv 里的 PySide6，项目本身只有几十 KB 脚本） |
| 运行内存 | **约 208 MB**（私有内存 318 MB） |
| CPU | 单核 **6.5%**，整机 **0.27%**（24 逻辑核） |
| GPU | `videodecode` 引擎约 58%，`3d` 引擎约 15%（均走硬件解码） |

> 若直接用 4K60 源片，内存会涨到约 580 MB、CPU 单核 11%，因为 4K 每帧缓冲就有 12 MB。
> 屏幕是 1080p 时，先用 `ffmpeg` 转 1080p 再喂给本工具，画质无损失、开销降一个量级，见下文「视频预处理」。

## 视频预处理（推荐）

```bash
ffmpeg -i "原始视频.mp4" -vf "scale=1920:1080:flags=lanczos" \
       -c:v libx264 -preset fast -crf 19 -pix_fmt yuv420p \
       -movflags +faststart -an "videos/output-1080p60.mp4"
```

- `scale=1920:1080` 按屏幕分辨率缩放，避免 4K 解码的 4 倍帧缓冲开销；
- `-an` 丢掉音轨（壁纸本来就不发声，省掉整条音频解码链路）；
- `-crf 19` 画质对壁纸场景足够，本机实测 17.2 MB 的 4K 源片转出来 **5.2 MB**。

## 工作原理

Windows 桌面由三层窗口协作绘制：

```
WorkerW                       <- 壁纸画在这层（图标层下方）
WorkerW                       <- 图标层宿主
  └ SHELLDLL_DefView
      └ SysListView32         <- 桌面图标
```

向 `Progman` 发送未公开消息 `0x052C`，资源管理器会分裂出一个**新的顶层 WorkerW** 作为纯壁纸层。
拿到它的 HWND 后，把无边框、不抢焦点的视频窗口 `SetParent` 挂上去，
视频就显示在桌面图标下方、所有普通窗口下方。

## 踩坑记录

开发过程中实际踩到的坑，按重要性排序：

### 1. `0x052C` 创建 WorkerW 是**异步**的

发完消息立刻 `EnumWindows` 会枚举不到，必须轮询等待（本项目等最多 3 秒）。
初次实现因为少了重试，直接找不到挂载点。

### 2. 子窗口的 `SetWindowPos` 用的是**父窗口客户区坐标**

视频窗口 `SetParent` 之后就成了子窗口，此时 `SetWindowPos` 的坐标**不是屏幕坐标**，
而是相对于父窗口客户区的。壁纸层 WorkerW 的客户区覆盖**整个虚拟桌面**，
多显示器时它的左上角通常在负坐标（本机是竖屏显示器的 `(-1080, -728)`）。

症状：只传 `(0, 0)` 会导致壁纸整体跑到竖屏上、再向右下溢出到主屏。
修复：先算屏幕坐标，再用 `MapWindowPoints(NULL, parent_hwnd, ...)` 换算成父客户区坐标。

### 3. 主窗口对象必须持有引用，否则进程会**静默崩溃**

`main()` 里若只写 `WallpaperApp(app)` 而不赋值给变量，
Python 的循环 GC 会回收该实例，连带销毁视频窗口和两个 `QTimer`；
在事件循环正使用定时器时销毁它，进程直接崩掉，而且 `pythonw` 没有控制台，
**崩溃是完全无声的**。

修复：`wallpaper = WallpaperApp(app)` 持有引用；
同时安装 `sys.excepthook` 把未捕获异常写进日志，避免以后再有静默崩溃。

### 4. `EnumChildWindows` 在 ctypes 里必须声明 `argtypes`

不声明参数类型时回调函数指针可能被截断成 32 位，导致枚举结果不可信
（排查时曾被误导）。本项目所有 Win32 调用都显式声明了 `argtypes` / `restype`。

## 托盘菜单

- 状态行：显示「播放中 / 已暂停（原因）· 目标显示器 · 视频文件名」
- 暂停 / 继续播放
- 更换壁纸视频…
- 显示在哪个显示器（自动列出所有显示器，标注横屏 / 竖屏与分辨率）
- 全屏应用时自动暂停（默认开）
- 开机自动启动
- 退出（恢复静态壁纸）

## 省资源设计

- 前台出现**占满整屏**的窗口（游戏、全屏播放器）时自动暂停解码，退出全屏自动恢复；
- **锁屏 / 远程会话断开**时自动暂停解码；
- 视频无音轨时不做任何音频解码；
- 每 5 秒自检一次：资源管理器重启导致父窗口失效时自动重新挂载；
- 显示器插拔 / 改分辨率后自动重新摆放。
